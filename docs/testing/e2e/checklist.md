# E2E manual test checklist (dev)

Version: 1.1
Author: Brandon Korous
Last Updated: 2026-07-12

Driven manually/by-agent via the `playwright-cli` skill against local dev — not committed as automated `*.spec.ts`. Personas referenced below (`persona-id`) are defined in [personas.ts](personas.ts); look up email/password/tenant there, don't duplicate credentials here.

Organized by module so items aren't repeated per persona. Each section lists **which personas exercise it** — run that section only against those personas. The [cross-reference matrix](#persona--module-matrix) at the bottom is the at-a-glance view.

**Depth expected:** for the module(s) it has enabled, each persona runs the FULL path — signup → onboarding module selection → every checklist item in that module's section, not a sample of them. A persona is not "done" until every item in every section it's listed under is checked. No single persona has to touch every module — but summed across all 12, every item in every section (§0 through the cross-cutting section) must end up checked by someone. If an item can't be checked off by any persona as currently defined, that's a gap in the persona set, not a reason to skip the item.

Check items off in place (`- [x]`) as you verify them per persona; note the persona id next to a checked item if a section applies to more than one, e.g. `- [x] apparel-co, food-bistro`.

**Out of scope for this pass:** blueprint _content/theme fit_ (e.g. an apparel persona landing on a food-themed blueprint) — blueprints are being rebuilt on silicaui and haven't been redone yet; don't file blueprint-selection mismatches as bugs during this pass.

**Production launch target: 2026-07-14** (set 2026-07-12, mid-sweep). From this point on, a bug found in this pass is a pre-launch blocker, not a backlog item — favor fixing over logging-and-continuing for anything plausibly launch-blocking (payment, checkout, data integrity, security, or — as it turned out — missing production infra for a feature whose code was already built).
